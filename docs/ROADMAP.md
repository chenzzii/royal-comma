# 後續開發建議（需要 Claude 先審查，非已完成）

## P0：先審查問題，不要急於重寫
1. 審查遊戲規則、分數與結算、所有關卡語意是否自洽，有沒有答案意外洩漏。
2. 核對所有 12 條跨關後日談及不同發生順序，檢查衝突或重複。注意 `makeChronicle` 對 crossover 有顯示最多四條的限制。
3. 驗證 BGM 切換、靜音、頁面切換和循環接點；不要只憑 `play()` 呼叫宣稱音樂聽感良好。
4. 改善可及性及低階手機上的操作，確保不是靠巨量連點或文字溢出製造難度。
5. 新增回歸測試覆蓋容易破壞的玩法規則。

## P1：劇情連續性 —— v4.1 已實作（見 `docs/PROGRESS.md`）
**目標**：之前某關若產生「熊公主」，後續的關卡判決及角色反應就會反映她的狀態，而不只是最終《王國正史》。
- 規劃 typed/structured 事件旗標或 `worldFacts`，從 `game.history` 決定，不寫死關卡順序。
- 至少加入 **4 組實際的中途連鎖事件**，例如：
  - 公主先救出魔王，再發生婚姻 → 婚禮與勇者反應改變；
  - 公主已嫁給魔王，後來才救援 → 新婚救援；
  - 國王已經成為龍的飼育員，後來直播賣魔藥 → 龍成為危險試用員；
  - 王子曾抓小偷，又開始處罰國王 → 形成自吹自擂的執法履歷。
- 必須**在判決當下**看到差異，且生成的最終故事不矛盾。
- 保持兩個合法逗號位置及原文不變；不可加提示。
- 自動化測試相同選擇不同順序、同 seed 重現、遊戲沒有變成死局。

## P2：策略深度與笑點密度
- 深入檢討混亂值與得分的風險回報是否有可被輕易計算的最優策略。
- 探索多種難度（不揭露位置、可選關卡池、有限提示、錯誤容忍度），但**絕不恢復回合委託**。
- 增加新關卡前要確保語義成立、兩個逗號都能形成合理而不同的語意、混亂分數可解釋。
- 可加入「宮廷新聞簡報」反映上一關政策，但不可淪為與玩家選擇無關的隨機文字。

## P3：音樂與演出
- 目前已有約 66.6 秒原創循環曲；若要再改善，優先處理尾端無縫 loop、配樂重複疲乏、音量平衡與事件音效層次。
- 可設計同一主題在高混亂時變調／伴奏變化，但不得無授權引用使用者提供的旋律。
- 第一版保留所有音量與開關控制，瀏覽器的使用者手勢播放限制不可忽略。

## P4：正式釋出前
- 原創素材／字體授權盤點、可讀性與無障礙、瀏覽器相容、行動裝置、完整部署 URL 測試。
- 視需要才評估 PWA、GitHub Pages 或 Cloudflare Pages；**目前尚未部署**。

## 每一階段的 DoD（完成定義）
- 有可觀察的玩家體驗改善、對應自動化測試、`npm test` 和 `npm run build` 通過。
- 瀏覽器可打開並至少實玩一場勝利與失敗；不具備環境就如實標示「未執行」。
- `docs/PROGRESS.md` 加入已修改檔案、可重現步驟與尚未解決的風險。
